# M2 recovery implementation and acceptance

Date: October 18, 2026 (America/Los_Angeles). Baseline: `a10c788`.
The user authorized finishing M2, then requested recovery commit `580b017` and
subsequently authorized pushing it to GitHub `main`. Mac acceptance remains pending.

## Acceptance and scope

A running countdown interrupted by sleep pauses; it does not earn suspended time
or silently resume during a maintenance wake. After a crash, restart, missed
checkpoint or clock discontinuity, Track shows the same session's saved work and
remaining duration. The user can explicitly continue that session excluding the
gap, or save confirmed time and finish. Retried requests save one decision, stale
tabs cannot resolve a newer interruption, and task completion remains separate.

Affected records: timer sessions, active intervals, operation receipts, and the new
schema-8 `timer_interruptions` table. Projects, tasks, placements, frozen weeks and
existing session history retain their records. The migration is additive; applied
migrations and dependency locks are unchanged. Automatic rewards, manual time
corrections and later milestones are outside this change.

## Implementation

- `backend/domain/timer.py`: measured-sleep pause, explicit same-session recovery,
  durable interruption details and resolutions, replay/revision validation. Paused
  timers remain paused across restarts. Running restarts keep only saved credit.
- Clock sources: measured Mac monotonic/continuous pair, Linux monotonic/BOOTTIME,
  Windows unbiased/continuous interrupt clocks. Unknown capabilities stay
  conservative and do not claim measured sleep. Windows selection is mocked here;
  this is not Windows hardware evidence.
- The entire unobserved checkpoint gap is excluded, including any awake portion.
  This intentionally favors conservative attribution over estimating work near
  sleep. Waking never resumes automatically; all subsequent DarkWake time stays
  excluded until the user's Resume. Sleep plus a simultaneous clock shift goes to
  Needs review. Wall timestamps never determine earned duration.
- `POST /api/timer/{id}/recover` requires a resolution, expected revision, operation
  UUID and explicit exclusion acknowledgment. Receipt, resolution and new interval
  or finished result commit together. Replaying an earlier request cannot resolve
  a later interruption or reopen a finished session.
- A backward wall-clock correction starts a fresh interval when resumed. Existing
  intervals are preserved and each new segment remains internally ordered; no
  artificial bridge across the clock change earns time.
- `Countdown.tsx`: confirmed time, checkpoint, interruption explanation and explicit
  continue/save controls; visible sleep pause with ordinary Resume. Requests retain
  their operation UUID and original revision after uncertain network failures.
  Browser interpolation is display-only.
- Fixed a pre-existing editor race: a delayed child/root save only closes its own
  editor, preserving another task editor and draft opened meanwhile. A deferred
  response frontend regression covers it.

Recovery does not infer or add missing time. The durable checkpoint is normally
about one second old; storage failures can make it older. Decisions retain an audit
record. There is no automatic undo that reintroduces excluded time.

## Target-Mac acceptance still required

The implementation review and physical/operator milestone gate are separate.
Automated midnight/DST, sleep/clock arithmetic and restart tests cannot certify
Mac power behavior.

1. Apply the reviewed changes on the target Mac, install the existing locks, build
   the interface and run the complete suite using its installed Chrome. Use a
   disposable data directory for all interruption tests.
2. Run `tools/m2_probe.py sleep --seconds 300 --output /tmp/m2-mac-sleep.json`.
   The tool launches its own synthetic session and reports its disposable service.
   Hide/close its browser as a control: the service must keep tracking while awake.
   Initiate an actual lid/OS sleep externally; the probe never suspends the machine
   or changes power settings. After waking, verify Paused or explicit Needs review,
   unchanged checkpoint credit through absence, and no automatic Resume. Exercise
   multiple suspend/maintenance-wake cycles; resume explicitly and finish once.
3. Repeat on battery and the supported standby/hibernate conditions. Record actual
   power configuration, measured clock/event observations and results. If a condition
   cannot be tested, leave it unverified; do not infer it from AC sleep.
4. Run `tools/m2_probe.py precision --seconds 600 --output /tmp/m2-mac-precision.json`
   alongside an external stopwatch. The proposed ten-minute precision target is
   within two seconds, with a single completed result and no task completion change.
   The probe's separate-process reference uses the same host clock and does not
   replace that external timing observation.
5. Demonstrate start from Plan/Track, pause/resume, page refresh/closure, two tabs,
   process crash/restart, explicit review/continue and finish retry. No uncertain
   interval may earn time and no duplicate outcome may be saved. Automated tests
   cover forward/backward clocks, midnight/DST and three-hour bounds; do not claim
   actual OS-clock or power changes from fake-clock evidence.

Probe exit codes: 0 means its measured scenario passed, 1 means failure, 2 means
observation/incomplete evidence (including no sleep or interrupted collection).
Retain sanitized JSON and the matching implementation revision. Normal personal
planner data is never used or changed by this tool. The historical M0 sleep probe
is retained for its recorded evidence; it is not a substitute for these timer checks.

and operator evidence is supplied and reviewed. No later build is started, no
