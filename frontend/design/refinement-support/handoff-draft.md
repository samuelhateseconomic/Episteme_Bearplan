## Observed repair coverage

- **Today:** compact heading/streak, explicit task counts, eight ordinary rows at
  split size, no automatic-priority styling, one working-content scroll owner.
  Compact disclosures fit their available width; long/enlarged text expands.
- **Week:** visible Previous/Today/Next, day counts, unique-leaf completion and
  progress, identified placement/source-day actions, readable two-line rows and
  a wider board with an optional Projects pane. End Week remains in the footer.
- **Projects/Done:** compact Rename/Add project order, bounded crowded task body,
  fixed Add task footer, grouped children and retained Notes after failed Save.
  Done is live completion by saved planned week; unique overall totals and frozen
  history remain separate.
- **Closure/carryover:** closure preview leads to choices with eligible tasks
  selected. Default is the last source planned date plus seven calendar days;
  eight Sunday examples suggest Nov 8 and citations suggest Wednesday Nov 4.
  Uncheck/redate precedes Review/Apply; preselection saves nothing. Cancel keeps
  the source closed. Missed comes from frozen closed-week state.
- **Track/recovery:** idle task selection, quiet owned-species choice, explicit
  session controls, same-session error/retry intent and visible confirmed,
  remaining and excluded time. The running session remains separate from task
  completion and finalized saved-time/streak credit.
- **Stats/Assistant:** time/current-completion/Missed scopes and chart dates are
  explicit; sources, context/model status and retained-question states stay quiet.
  The Assistant frames intentionally cover a read-only layout subset; current
  app M5 Apply/Undo/carryover capability is not removed by that sample.
- **References/canvas:** light/dark and compact/split/wide compositions, crowded
  content, enlarged-text stress and native Sections support review. Preserve the
  free two-dimensional editing canvas rather than an enclosing page-sized frame.

These are rendered/structural observations. Final R21 integration may change
labels, counters and routes; recheck only its affected visible dependents.

## Responsive and keyboard intent

- Primary reference sizes: 640×800, 800×900 and 1440×900; the 1279/1280 transition
  comparison remains a design proposal rather than measured Mac hardware behavior.
- Use readable wrapping and growing rows. Preserve target areas, context and
  actions before reducing text size. The enlarged-text Figma fixture demonstrates
  larger text; it is not a browser 200% reflow test.
- Each working context has a clear vertical scroll owner. The wide board may use
  horizontal scrolling with separate day lists when the Projects pane is open;
  fixed footers must not cover the last reachable task.
- Intended keyboard flow is navigation → view/project controls → task/disclosure
  controls → selected-placement actions. Retain date/keyboard movement alternatives,
  first/last ordering boundaries, Escape/cancel routes and visible focus.
- Parent containers expose disclosure/progress, not direct completion or Start.
  Leaf completion/reopen retains focus as rows move. Closed snapshots are read-only.
- Gray checked rows remain readable and operable; status also has text/checkmarks.
  The corrected dark accent has sampled contrast margin. This is not a complete
  accessibility or screen-reader conformance claim.

## Verification and pending user walkthrough

Keep evidence types separate:

1. **Rendered:** inspected frames and normal-size text/control geometry.
2. **Structural:** component/variable IDs, bounds, scroll configuration and native
   reaction schema/destinations.
3. **Modeled:** finite interpreters/offline mocked-AST checks against specified
   cases; these do not execute the Figma presentation or app.
4. **Executed:** actual preview clicks/scrolling/keyboard; still pending where
   computer-control startup is unavailable. No success may be inferred from 1–3.
